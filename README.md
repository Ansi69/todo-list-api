# Описание проекта

**to-do list**

Цифровая платформа по управлению личными заметками "to-do list" - это API для управления задачами
(to-do list). Оно позволяет пользователям создавать, редактировать, удалять и просматривать задачи. API поддерживает
сортировку, фильтрацию, пагинацию и авторизацию пользователей.

## Баз данных

### Важно!

В проекте используется две базы данных: основная БД для хранения данных приложения и отдельная БД для хранения логов
пользователей. Это нужно учитывать при разработке, так как модель `ActionLog` использует
отдельное подключение `db_logs`. При необходимости объединить (join) данные основной базы данных и базы данных логов
используется подход с использованием сырого SQL-запроса и функции json_to_recordset.

### Импорт БД

На данный момент не используется механизм миграций для создания схем БД, поскольку сидеры для
заполнения данных не реализованы. Вместо этого применяется дамп, который накатывается на пустую базу данных.

1. Создайте новую базу данных
    ```bash
    createdb -U sovhoz sovhoz-db-name
    ```
2. Импортируйте данные из дампа
    ```bash
    pg_restore -U sovhoz -d sovhoz-db-name dumpname.sql
    ```

* Для обновления БД из дампа потребуется удалите текущую БД и повторить шаги 2 и 3:

    ```bash
   dropdb -U sovhoz sovhoz-db-name
   ```

## Git Flow

1. Основные ветки:
    * `master` — стабильная версия
    * `develop` — ветка для интеграции всех фич и исправлений
2. Работа с фичами:
    * Создавайте ветку `feature` от `master`
    * Ветка должна включать в себя краткое описание задачи и номер задачи в jira
    * Пример `feature/SOV-14668-Актуализация-readme`
3. Исправление критических ошибок:
    * Создайте ветку `hotfix` от `master`
    * Ветка должна включать в себя краткое описание задачи и номер задачи в jira
    * Пример `hotfix/SOV-14666-Исправление-работы-сервиса-логов`

`
После завершения работы сливайте ветку в master через merge request
`

## Code conventions

* Если делаем команду для одноразового применения:
    * Кладем её в [Tmp](app%2FConsole%2FCommands%2FTmp)
    * Весь код реализуем прям в ней чтобы не было мусора в регулярном коде
    * В PHPDoc делаем TODO с пометкой о том, что нужно удалить команду и указываем дату комментария,
      например `TODO: remove 20241231`

## Запуск тестов

### Локальный запуск тестов

Для запуска Unit-тестов используйте следующую команду Artisan:

```bash
   php artisan test
   ```

### Запуск API-тестов через Jenkins

В Jenkins для API-тестов можно просматривать подробную информацию о каждом
тестовом прогоне и запускать пайплайн тестов вручную.

Тестирование происходит в stage окружении и занимает до 40 минут.

Чтобы запустить новый прогон тестов:

1. Перейдите в [Jenkins](https://web.jenkins.eltc.ru/view/SovhozAI/job/SOVHOZ_api_test/) и
   нажмите `«Собрать с параметрами»`
2. Нажмите `«Собрать»`
